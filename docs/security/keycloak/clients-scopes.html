Clients & scopes

Besides Keycloak’s built-in clients (account, account-console, admin-cli, broker, realm-management, security-admin-console), the realm (KEYCLOAK_REALM, crisalid-inst by default) declares four clients and two client scopes.

Client Used by Capabilities Default scopes (added to the built-in ones) Access token lifespan Secret
sovisuplus SoVisuPlus: user login (NextAuth) Client authentication, Standard flow crisalid-agents-audience 15 min SOVISUPLUS_KEYCLOAK_CLIENT_SECRET
open-webui OpenWebUI: user login (OIDC) Client authentication, Standard flow crisalid-agents-audience 15 min OPENWEBUI_KEYCLOAK_CLIENT_SECRET
crisalid-agents CRISalid agents chat API (token exchange) and batch entry points (service account) Client authentication, Service accounts roles, Standard token exchange crisalid-graph-mcp-audience realm default CRISALID_AGENTS_KEYCLOAK_CLIENT_SECRET
crisalid-graph-mcp MCP toolbox (neo4j-mcp), as a resource server Client authentication, no flow at all none not applicable unused

Other settings of the clients:

  • sovisuplus: Valid redirect URIs ${SOVISUPLUS_URL}/*; a user-attribute mapper exposing the orcid attribute as a claim.
  • open-webui: Valid redirect URIs ${OPENWEBUI_URL}/oauth/oidc/callback and http://localhost:8080/oauth/oidc/callback (local instance), Valid post logout redirect URIs ${OPENWEBUI_URL}/*, Web origins ${OPENWEBUI_URL}.
  • crisalid-agents and crisalid-graph-mcp: no URL of any kind; they never take part in a browser flow.
Client scope Mapper Attached as Default to
crisalid-agents-audience Audience, Included Client Audience = crisalid-agents, access token only sovisuplus, open-webui
crisalid-graph-mcp-audience Audience, Included Client Audience = crisalid-graph-mcp, access token only crisalid-agents

The two audience scopes make a token valid for exactly one service. A token issued to sovisuplus or open-webui carries aud: crisalid-agents: the chat API accepts it, the toolbox rejects it. A token obtained by crisalid-agents (exchanged from a user token, or its service account) carries aud: crisalid-graph-mcp: the toolbox accepts it, the chat API rejects it. The crisalid-graph-mcp client exists only to be named as an audience; it never authenticates and no token is issued to it. How the services use these tokens is described in Crisalid AI → Security.

Manual configuration

Admin console, realm crisalid-inst. Create the clients first: the audience mappers select a client from a list.

  1. Clients → Create client sovisuplus (usually present already): Client type OpenID Connect; Client authentication on; Standard flow on; Direct access grants and Service accounts roles off. Valid redirect URIs ${SOVISUPLUS_URL}/*. Credentials → copy the secret into SOVISUPLUS_KEYCLOAK_CLIENT_SECRET (docker/.env).
  2. Clients → Create client open-webui: Client authentication on; Standard flow on; Direct access grants off. Valid redirect URIs ${OPENWEBUI_URL}/oauth/oidc/callback (and http://localhost:8080/oauth/oidc/callback for a local instance), Valid post logout redirect URIs ${OPENWEBUI_URL}/*, Web origins ${OPENWEBUI_URL}. Credentials → copy the secret into OPENWEBUI_KEYCLOAK_CLIENT_SECRET.
  3. Clients → Create client crisalid-graph-mcp: Client authentication on; every flow and Service accounts roles off. No URL.
  4. Clients → Create client crisalid-agents: Client authentication on; Service accounts roles and Standard token exchange on; Standard flow and Direct access grants off. No URL. Credentials → copy the secret into CRISALID_AGENTS_KEYCLOAK_CLIENT_SECRET.
  5. Client scopes → Create client scope crisalid-agents-audience: Type Default, Protocol OpenID Connect, Display on consent screen off, Include in token scope off. Then Mappers → Configure a new mapper → Audience: Included Client Audience crisalid-agents (pick the client; leave Included Custom Audience empty), Add to access token on, Add to ID token off, Add to token introspection on.
  6. Client scopes → Create client scope crisalid-graph-mcp-audience, same settings, with an Audience mapper whose Included Client Audience is crisalid-graph-mcp.
  7. Clients → sovisuplus → Client scopes → Add client scope crisalid-agents-audience, assigned type Default. Same for open-webui.
  8. Clients → crisalid-agents → Client scopes → Add client scope crisalid-graph-mcp-audience, assigned type Default. Keep the built-in service_account scope.
  9. Clients → sovisuplus → Advanced → Advanced settings: Access Token Lifespan 15 minutes. Same for open-webui.
Audience mappers must name a client

Keycloak’s standard token exchange only grants an audience that is a client of the realm and that the requesting client reaches through an Audience mapper of its Default scopes. A mapper with a custom audience string, or the scope assigned as Optional, makes the exchange fail with Requested audience not available. The toolbox, for its part, only compares the string: that is why the value must be the client ID crisalid-graph-mcp on both sides (MCP_AUDIENCE of neo4j-mcp).

Verification

In the console, Clients → client → Client scopes → Evaluate, pick a user and open Generated access token:

  • sovisuplus and open-webui: aud contains crisalid-agents and not crisalid-graph-mcp; azp is the client ID; exp is 15 minutes after iat; preferred_username and email are present.
  • crisalid-agents: aud contains crisalid-graph-mcp.

From a shell, with $ISSUER the public issuer (https://<keycloak-host>/realms/crisalid-inst) and $SECRET the secret of crisalid-agents:

# service account: aud must contain crisalid-graph-mcp
curl -s "$ISSUER/protocol/openid-connect/token" \
  -d grant_type=client_credentials \
  -d client_id=crisalid-agents -d client_secret="$SECRET"

# token exchange: $USER_TOKEN is an access token of sovisuplus or open-webui
curl -s "$ISSUER/protocol/openid-connect/token" \
  -d grant_type=urn:ietf:params:oauth:grant-type:token-exchange \
  -d client_id=crisalid-agents -d client_secret="$SECRET" \
  -d subject_token="$USER_TOKEN" \
  -d subject_token_type=urn:ietf:params:oauth:token-type:access_token \
  -d audience=crisalid-graph-mcp

The exchanged token keeps the user’s sub, preferred_username and email, carries aud crisalid-graph-mcp and azp crisalid-agents, and expires with the subject token. A 400 invalid_request with Requested audience not available points to steps 3, 6 or 8; a 403 to Standard token exchange being off on crisalid-agents; a rejected subject token to a token without the crisalid-agents audience (step 7).
